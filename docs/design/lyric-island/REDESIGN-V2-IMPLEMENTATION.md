# Lyric Island 第二轮｜实现、兼容与验证边界

2026-10-19。原始集成基线：`12df41685d615e11c211ad713e639a68f1e4a5ac`。
当前源码身份以 GitHub commit 为准；本文件记录实现与验证范围，Obsidian Handoff 是当前交接主源。

## 决策与完成边界

用户要求整轮持续实施，不再逐批占用其桌面或等待转发；允许正常同步 GitHub。
保留性能保护与原有资产，不把用户取消繁琐手动验收误写成“性能已通过”。
这一版本是原生源码集成，不是回滚到 v0.1.2、另一套 Web 播放器或新的任意组合系统。

- 五个主场景：原版环境光、流动光场、封面写真、唱片内页、专注歌词。
- 原版、经典放大/纯高斯、完整羽化仍可直接返回；不只埋在历史备份里。
- 八套旧 rawID、用户原有偏好和已选画面保留。没有新场景存档时先按原画面启动。
- 新场景选择和参数与旧渲染器分开；每个新场景仅有适用的有限风格。
- 此时只创建当前场景的歌词树，缩略图用轻量构图和共享封面，不预建五份实际播放界面。

## 1. 五场景与旧效果

|场景|实际组织|无前景封面时|
|---|---|---|
|原版环境光|复用 authenticAmbient 的已认可绘制；完整封面与同步歌词并重|真实背景纹理仍保留，读区扩展|
|流动光场|classic 色场不再重复放大人物；可选择现有完整羽化渲染|曲目题头、色场、受控阅读区|
|封面写真|ambient / classicGaussian / stage 的有限预设，保留不同裁切和柔化方式|背景仍是主图，不强制重复大封面卡|
|唱片内页|albumPoster 基础上的独立题头、细分隔、封面列和段落阅读|题头与段落结构保留，不退化为大字播放页|
|专注歌词|quiet 色底、稳定行宽和多层文字；可选小封面|默认为无大封面的连续阅读|

新场景原版/羽化/柔焦/纯高斯各自持久化 blur、前景尺寸/位置、背景取景和歌词位置等适用参数。
不适用的设置不展示。照片/专注的小缩略图不假装可以使用旧大封面尺寸滑块。
隐藏标准播放器时不再创建空脚注及间距。流动光场与唱片内页有确定性高度预算，短/窄窗口保住阅读区与底部控制。

## 2. 操作结构与工具窗

主窗提供歌词库、搜索、译文、调整及设置直达；当前歌词的来源/版本等仍复用现有操作。
常用译文显示、已存版本和翻译本首不等于 API 服务配置；AI 模型、强度、会话留在全局 AI 设置。

- 固定调整面板复用独立 NSPanel，优先主窗右侧 12pt、宽360pt；不足放左侧，两边不足则当前屏内浮动。
- 不修改主窗 frame，不扣减歌词/封面的可用宽度；全屏浮窗不自动跳去另一屏。
- 临时悬停打开与点击固定保留；固定工具不被另一个入口的悬停替换。
- 关闭时释放宿主内容并移除相关观察，不在后台保留完整预览树。
- “更多画面选项”无存档时展开，之后记忆手动折叠；内部按背景、封面、播放组织。
- 场景标题旁有“悬停预览”。老用户有渲染偏好时沿用开，新用户默认关；停留200ms临时预览，离开恢复，点击才保存。
- 预览不触发歌词搜索/翻译、不修改其他场景；取消任务/关闭面板时清掉临时预览。
- 统一 V3NumericSlider：标签与单位、滑块、下方可编辑数字。数字完整解析、有限值检查、范围夹紧、键盘提交，和滑块同一绑定。
- 主窗/桌面/胶囊/菜单及设置中的常规字号、大小、宽度等沿用此组件；播放 seek 保留专用控件。

## 3. 明亮封面与共同设计语言

“歌词清晰度保护”提供自动、加强、关闭，不再仅舞台可用。
复用一次封面取色的缓存，在阅读区使用稳定局部保护；原文、译文、读音以及状态/错误说明共用这个读区。
不逐帧采样屏幕，不用全屏忽暗忽亮制造对比。
管理页保持中性表面，听歌页可有专辑光色；继续使用原 LyricsDesignTokens，减少重复品牌页眉与叠加底板。
已有歌词库/编辑器的预览、采用、编辑为新版本、锁定和手选保护没有另造一套数据库或入口语义。

## 4. 边缘播放

- 当前接近哪条边，就以该边作锚点；历史退出点仅兜底。
- 被动感应30pt、保持46pt，按钮与连接区域锁定；明显沿边离开/换边再定位。阈值是实现值，不宣称已由用户实测最优。
- 进度线常驻，只有按钮显隐；0.16秒淡出与减少动态保留。
- 扩大被动感应，不扩大原有窄 seek 带；跟踪 NSView 不吞点击，非主窗口仍用 activeAlways。
- 拖动保留歌曲身份，换歌后旧手势不得 seek 新歌；释放后立即重新判断位置。
- 无全局鼠标脚本、无新 Timer；仅局部状态真正改变才写 SwiftUI State。
- 固定/自动流转/每首随机保留，新增“跟随封面”；颜色来自同一封面缓存。
- 边线与按钮在同一局部颜色时钟内更新，减少动态或不可见时停止装饰更新。

## 5. 状态栏与辅助显示

- 菜单弹窗短歌词按内容预算，不再固定留100/128pt歌词空区或150pt设置空区。
- 播放页保留曲目、歌词、控制与捷径；文字外观独立页返回，完整歌词另页。
- 同一首歌的高度预算不随每次播放tick/换行跳动，达到上限后才滚动。
- 占用宽度提供自适应上限/固定，默认240pt，范围120–480pt，精确数字可改。
- 超长显示提供缓慢滚动/省略，短句不动；固定占位不推挤相邻项。
- 只对实际溢出的可见长句做局部 Core Animation；暂停、减少动态和不可见时停止。
- 注音/译文沿用原生绘制，长文本图像有4096pt上限和缓存键，文字完整提示保留。
- 菜单歌词关闭时，外观页仍可编辑并有预览。
- 桌面、胶囊继续使用既有歌曲/文字投影与独立偏好，隐藏内容释放和时钟过滤保留；不将主窗五套背景复制成五个后台窗口。

## 6. 歌词正文、身份与服务错误

新增通用 `LinkCoreLyricsProvider` 并接入来源配置、模型、搜索管理和持久化。
发现路线为官方艺人目录 → 同一艺人实体的发行/歌曲目录 → 匹配歌曲的公开歌词页，不逐首硬编码。

- 正文页独立标题/艺人必须与目录相符；可信日/英标题和艺名别名绑定发行方实体。
- 版本标签与时长继续参与校验，普通/Piano/加速/现场不能因同名混用。
- 可靠纯文本可先被采用，明确未同步，不伪造逐行轴；现有轴/译文后续补全继续复用。
- 请求范围有界、同请求去重、有超时、最多1.5MB流式上限；解析后保留小型有界缓存，不保留全站HTML。
- 服务失败不负缓存成长期“无歌词”；匹配目录但无正文与500/503等错误分别呈现。
- lyrics.ovh 的查询回显仍不能作独立身份，不能因为官方存在同名目录就把其任意正文改成自动可信。
- 错误区缩成曲目状态、一个主要操作和展开详情；HTTP列表默认收起，“标记纯音乐”在更多菜单，不推荐把搜索失败当纯音乐。
- 人工采用、锁定、缓存、live/preview和已发送请求去重保护不变；不新增收费模型或复制登录凭据。
